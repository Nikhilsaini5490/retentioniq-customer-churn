# RetentionIQ

**Customer churn risk and retention analytics** built with Python, pandas, scikit-learn, Streamlit, and FastAPI.

RetentionIQ demonstrates an end-to-end data-science workflow: validate tabular data, compare interpretable and ensemble baselines, evaluate on a stratified holdout, inspect churn segments and global feature importance, score new customer records, and expose predictions through a documented API.

> **Data integrity notice:** the included offline demo dataset is synthetic. Its metrics demonstrate that the pipeline runs; they are not real-world performance claims. This is an educational, production-oriented prototype, not a validated system for customer decisions.

## Features

- Reproducible synthetic-data generator and strict training-schema validation.
- Train-only preprocessing with median imputation, scaling, and unknown-safe one-hot encoding.
- Logistic Regression and Random Forest comparison using a stratified 75/25 split.
- Holdout accuracy, precision, recall, F1, ROC-AUC, PR-AUC, and confusion matrix.
- Permutation feature importance measured on holdout data.
- Streamlit portfolio dashboard, interactive single-customer assessment, optional new-customer CSV scoring, and exports.
- FastAPI `/health`, `/predict`, and `/predict/batch` endpoints with request validation.
- Versioned model artifact metadata, automated tests, Windows launchers, and Docker Compose.

## Quick start on Windows

Open PowerShell in this folder:

```powershell
python --version
python -m venv .venv
.\.venv\Scripts\Activate.ps1
python -m pip install --upgrade pip
python -m pip install -r requirements.txt
```

Launch the dashboard:

```powershell
streamlit run app.py
```

Open `http://localhost:8501`. The first analysis trains and caches two baseline models. To start the API and dashboard in separate windows, run `run_project.bat`. The API is available at `http://127.0.0.1:8000/docs`; its launcher creates a local model artifact from synthetic demo data before starting.

## Dataset workflow

The dashboard works offline with 2,400 reproducible synthetic records. Download a sample CSV from the sidebar, or generate a file from PowerShell:

```powershell
python scripts/generate_demo_data.py --rows 2400 --seed 42
```

For an academic experiment, select **Upload CSV** and provide a labeled training dataset matching [the data schema](docs/DATA_SCHEMA.md). To score a separate unlabeled customer cohort, use **New customers to score**. Do not use model metrics from synthetic records in a report as if they came from real customers.

## Train and serve the API

Train an artifact and print its metadata:

```powershell
python scripts/train_model.py
```

Start FastAPI (after activating the project environment):

```powershell
$env:PYTHONPATH = "src"
python -m uvicorn retentioniq.api:app --reload --host 127.0.0.1 --port 8000
```

The generated artifact is written to `artifacts/churn_model.joblib` and is ignored by Git. The API only loads trusted local artifacts generated by this project; do not load model files from untrusted sources. To use a different path, set `RETENTIONIQ_MODEL_PATH` before starting Uvicorn.

Example request:

```powershell
curl.exe -X POST http://127.0.0.1:8000/predict `
  -H "Content-Type: application/json" `
  -d '{"customer_id":"demo-001","tenure_months":8,"monthly_charges":79.5,"contract":"Month-to-month","internet_service":"Fiber optic","support_tickets_90d":3,"payment_method":"Electronic check","paperless_billing":true,"autopay":false,"senior_citizen":0}'
```

Batch requests accept 1-500 customer records. See `/docs` for the interactive OpenAPI contract.

## Docker

With Docker Desktop running:

```powershell
docker compose up --build
```

Open the dashboard at `http://localhost:8501` and API docs at `http://localhost:8000/docs`. The API container trains its demo artifact during startup and stores it in a named volume. For external datasets, replace that demo training step with a reviewed data pipeline before deployment.

## Limitations and responsible use

- A random holdout on a synthetic dataset does not establish real-world generalization, temporal stability, probability calibration, or business value.
- Use time-based or customer-grouped validation where the real data's time/group structure requires it; avoid target leakage.
- Feature importance describes model reliance, not cause. Profile flags are descriptive, not explanations of why an individual will churn.
- Demographic or proxy fields can create unfair outcomes. Review necessity, subgroup performance, privacy, consent, retention, and human review before any real deployment.
- Thresholds should be chosen using intervention costs, capacity, and validated false-positive/false-negative costs; the default is only a demonstration setting.
- A production deployment additionally needs authentication, authorization, encrypted transport/storage, monitoring, drift and calibration checks, auditability, model approval, incident response, and a governed retraining process.
